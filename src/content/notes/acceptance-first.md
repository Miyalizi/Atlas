---
title: 先写验收标准，再让 AI 动手
date: 2026-10-15
tags: [AI编程, 工作流]
description: “做好了”的定义要在开工前定下来。
---

Agent 最常见的失败不是写不出来，而是**做了别的事**，或者**觉得自己做完了**。

办法很简单：每个任务开头写三到五条验收标准。例如：

```
任务：文章页加阅读进度条
验收：
1. 滚动时顶部出现进度条，到文末为 100%
2. 不引入新依赖
3. 移动端不遮挡标题
4. npm run build 通过
5. 关闭 JS 时页面正常显示，只是没有进度条
```

好处：

- Agent 有明确的终点，不会无限发挥。
- 审查时逐条核对，快很多（见[审 AI 写的代码](/posts/review-ai-code/)）。
- 能自动化的标准（构建通过、测试通过）可以交给 [Hook](/notes/claude-code-hooks/) 强制检查。

这也是 [Harness 工程](/posts/harness-engineering/)里“生成和评审分开”的最低成本实现。
