当 Agent 一下午能交出几千行改动，**审查能力**就成了个人开发者最重要的技能。

## 审查顺序

1. **先看测试**。测试是你和 Agent 之间的合同：它测了什么、没测什么？有没有为了让测试通过而改测试？
2. **再看 diff 范围**。改动是不是超出了任务？“顺便”改的东西最容易出问题。
3. **看边界**：空值、错误处理、并发、权限。AI 写的代码在主路径上通常没问题，问题集中在边角。
4. **看依赖**：新增了什么包？真的需要吗？
5. **最后看风格**：交给 formatter 和 lint，别浪费注意力。

## 让 AI 帮你审

- **换一个会话、最好换一个模型来审**。同一个会话里的 Agent 倾向于为自己辩护。
- 给审查者明确的清单：安全（见 [vibe coding 安全清单](/posts/vibe-coding-security/)）、性能、和需求是否一致。
- 让它给出文件和行号，你逐条判断。

Anthropic 的 Code Review 在 10 月加了 Quick、Standard、Deep 三档审查强度，可以按仓库设置。

## 降低审查负担

- 任务拆小，一个 PR 只做一件事。
- 动手前先写好验收标准，见[先写验收标准](/notes/acceptance-first/)。
- 关键规则用 [Hooks](/notes/claude-code-hooks/) 自动检查，审查时就不用再看。
