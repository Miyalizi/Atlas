这个博客本身就是我用这套流程做出来的：三个周末，一个 Claude Pro 订阅，加上一点 DeepSeek API 的零钱。下面按顺序讲每一步怎么做，也讲哪里翻过车。

## 1. 想法 → 一页需求

我先和旗舰模型聊了一个晚上，只问三个问题：给谁看、解决什么问题、第一版只做哪三件事。最后落下来的是一页纸：

- 给谁：我自己，以及偶尔路过的读者。
- 解决什么：文章写完就沉下去，彼此没有关系。
- 第一版只做：Markdown 写作、站内双向链接、能搜索。

这页纸存进仓库，后面每次 Agent 想“顺手”加功能，我就把它甩回去。**第一版做什么不重要，不做什么才重要。**

## 2. 搭骨架：一小时省十小时

新建仓库后，我做的第一件事不是写页面，而是写规则：

- [AGENTS.md / CLAUDE.md](/posts/agents-md-guide/) 写清楚技术栈、目录结构、命名习惯，还有一句“改样式后必须截图给我看”。
- 配好格式化和构建检查，用 [Hooks](/notes/claude-code-hooks/) 在每次编辑后自动跑构建，失败时把报错直接喂回去。

这一步花了一小时左右，换来的是后面几十次修改里，Agent 很少交出一个连构建都过不了的版本。

## 3. 拆任务、并行做

需求拆成互不冲突的小任务，每个都带[验收标准](/notes/acceptance-first/)。比如“文章页底部显示引用了本文的内容”，验收标准写的是：

> 构建通过；被引用三次的文章底部显示三条，每条带引用所在的那句话；没有被引用的文章不显示这个区块。

然后用 [Claude Code 桌面版](/posts/claude-code-desktop/)开三个会话并行跑：一个做双向链接，一个做搜索，一个做深浅色。三件事碰的文件几乎不重叠，所以基本没有冲突。

## 4. 审查：截图比 diff 好用

代码我会看，但更有效的是看截图。这个博客翻过的几次车，全是在截图里发现的：

- **首页星图一团乱麻**。五十多个节点挤在一起，标题叠成一片。代码完全没错，测试也全过，但就是难看。最后改成默认只给引用最多的几篇写标题，其余悬停才显示。
- **列表里的缩略图在添乱**。每行一张小封面，看起来很“丰富”，实际上每张都差不多，只是噪音。删掉之后反而清爽了。
- **中文两端对齐被拉出字距**。中英混排的行会被撑开，像“系 统 提 示”。改成左对齐就好了。

这三个问题没有一个能写成自动化测试。所以我的规则是：**改了样式，就要给出改前改后的截图，深浅两套、桌面和手机各一张**。安全方面单独开一个会话审，清单见[审 AI 写的代码](/posts/review-ai-code/)和[安全清单](/posts/vibe-coding-security/)。

## 5. 上线

静态站点放在 Cloudflare Pages，免费，推送到 main 就自动部署，每个分支还有自己的预览地址。我让 Agent 开的每个 PR 都附预览链接，在手机上点开看一眼再合并。

有后端的项目会麻烦得多，数据库权限一定要逐表检查，这是 vibe coding 最常见的漏洞。

## 6. 维护交给自动化

依赖升级、死链检查这类杂活，交给 [Routines](/posts/claude-code-routines/) 每周跑一次，产出一律开 PR，我只负责点合并。

## 7. 成本

三个周末下来的账单：

| 项目 | 花费 |
| --- | --- |
| Claude Pro | $20（一个月） |
| DeepSeek API | 不到 ¥10，用来批量生成摘要初稿 |
| 域名和托管 | 0，先用 pages.dev 的免费域名 |

几乎没碰到 Pro 的 5 小时上限，因为大部分时间花在想清楚要什么、看截图上，而不是让 Agent 狂写。账单怎么管见[别让账单失控](/posts/ai-cost-control/)。

## 回头看

最大的收获是分工变了：**我负责定方向、写验收标准、挑毛病；Agent 负责实现和自证**。写代码不再是瓶颈，瓶颈变成了“我到底想要什么”和“我能不能看出哪里不对”。
