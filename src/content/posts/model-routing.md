不是每一步都需要最强的模型。一个典型的编程任务里：

- **理解需求、出方案、审代码**：需要判断力，用旗舰。
- **按方案改文件、跑测试、修小错**：需要执行力，中档就够。
- **搜代码、读文档、整理日志**：体力活，用最便宜的。

## 三种做法

1. **手动切换**：Claude Code 里用 Opus 5.5 出计划，切到 Sonnet 5.5 执行。最简单，也最常用。
2. **子 Agent 用便宜模型**：主 Agent 用旗舰，搜索、整理类子任务派给 Haiku 5.5 或 DeepSeek Flash。Claude Code 支持给子 Agent 单独指定模型。
3. **Advisor 模式**：执行者用中档模型，遇到难点时请教旗舰模型。Claude 的 API 和 Claude Code 都有相关能力。

## 一个反直觉的地方

切模型有代价：**提示缓存按模型隔离**，换模型后缓存失效，长对话里频繁切换可能反而更贵。另外，新一代旗舰降低推理强度（effort）后，表现常常不输上一代的高强度设置。

所以在做复杂的多模型级联之前，先试试“**同一个旗舰，调低强度**”，比如 Opus 5.5 用 medium 而不是 max。很多时候这就够了，还更省事。

## 我的分工（2026 年 10 月）

| 环节 | 模型 |
|---|---|
| 方案、架构、代码审查 | Claude Opus 5.5 |
| 日常实现 | Claude Sonnet 5.5 / GPT-6.1 Sol |
| 前端 UI | Kimi K3 或 Qwen3.8 Max（试验中） |
| 批量、搜索、摘要 | Haiku 5.5 / DeepSeek V4.1 Flash |
| 超长文档 | Gemini 4 Argon |
